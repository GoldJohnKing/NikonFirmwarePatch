# v0.4.1 验证范围 / Validation coverage

本版 v0.4.1（本 fork，基于上游 XinmiaoZhao v0.4.0）以用户自行取得的原厂 Z8 C 3.11 为输入。上游 v0.4.0 的源码、预编译单元和固件补丁与其 v0.4.0-rc.2 相同，曾对 15 种组合逐组合独立解封装，核对身份、补丁窗口、未改动字节、共享菜单和资源边界，并比对源码重编与预编译单元，四组功能的行为证据沿用。本 fork 新增第五组 `video-orientation` 与自定义快门声，非空组合增至 31 种，证据见下表。构建时选择的固件版本号用于区分文件；以下按功能组合说明证据。

## English

This release, v0.4.1 in this fork, builds on upstream XinmiaoZhao v0.4.0 and takes the user-supplied original Z8 C 3.11 as its input. The upstream source, compiled units and firmware patches match v0.4.0-rc.2; upstream independently decoded all 15 of its selections, checked identity, patch windows, preserved bytes and shared-resource boundaries, and compared source rebuilds with the precompiled units, so the four upstream groups' behavioural evidence carries over. This fork adds the fifth group `video-orientation` and the custom shutter sound, raising nonempty selections to 31. The original package is checked before building. Each bounded emulator run boots decrypted MAIN with synthetic peripherals, enters the firmware version page twice and stops at the update entry. Before the v0.4.1 release, two additional full-system smoke runs booted to shooting-ready in z8-qemu, the five-group full selection (04.06.p0) and the same selection stacked with the custom shutter sound (04.06.w0): each passed all 208 runtime checks with zero exception events, and a scripted RAW capture with the published fixed key sequence wrote a complete DCIM/100NCZ_8/DSC_0001.NEF (35,110,512 bytes) to the card.

The upstream v0.4.0 all-feature firmware was tested on a Z8. A previously recorded S-Log3 N-RAW clip and a newly recorded Log3G10 clip showed the correct names in playback. The tester confirmed the expected assist rendering; the photographs document the label and ASSIST indicator. Display colour accuracy was not measured.

The fifth group `video-orientation` ships in this fork's v0.4.1. Its offline checks pass: the full unit suite, `verify.py` on the single-group and four-video-groups-plus-orientation outputs, and the frozen 31 combination recipes. The full 31-leg validator run completed on 2026-11-15 against the v0.4.1 toolkit: all 31 legs pass and all 44 negative controls are rejected. Source/prebuilt equivalence is scoped per unit: seven units reproduce their pinned bytes exactly under LLVM 19.1.7; the three units pinned with Apple clang 21.0.0 (pixelshift, pixelshift-af, precapture) reuse the released upstream v0.4.0 bytes, double-checked at packaging against the upstream archive digests and this repository's pinned recipes. Emulation passes: full-system boot with zero exception banners, first-open arming with idempotence, the stock boolean value render and per-bank carrying across menu-bank switches. On the camera, the menu behaviour matches the shipped H.265 tier feature exactly, and every format the camera records is verified per grip (H.265 10-bit and 8-bit MOV, H.264 8-bit MP4/MOV, N-RAW with its simultaneous proxy, ProRes RAW 10/12-bit with proxies), with every file checked through ffprobe. See the [video-orientation guide](video-orientation.md).

The custom shutter sound passes the 32-selection offline matrix (any nonempty combination of the five feature groups plus the sound, or the sound alone on a version-stamped stock base) with independent verification after every build, byte-exact source/prebuilt parity under LLVM 19.1.7, seven negative controls rejected as expected, and the upstream 27+13 ARM regressions. A four-group base plus the custom shutter sound passed complete on-camera verification. See the [custom shutter sound guide](custom-shutter-sound.md) and the v0.4.1 changelog section.

Earlier all-feature camera checks on the same recording and photo implementations covered four decoded ProRes HQ/LT recordings, 99 decoded pre-capture NEFs and 59 matching JPEGs, DX/FX lossless-to-HE★ fallback, and two fully decoded 4-/16-frame pixel-shift merges from non-default starting file numbers. The tester also reported normal lit AF points with desqueeze. Menu-bank/power-cycle transitions and individual playback icons, small-viewfinder or subject-detection geometries remain separate checks.

See the [colour measurements](log-colour-report.en.md), [known limitations](known-issues.md) and [Windows toolkit CI](https://github.com/GoldJohnKing/NikonFirmwarePatch/actions/workflows/host-checks.yml). Windows jobs build on Python 3.12 and 3.13 using the released ZIP and verify the full-selection output against the supplied reference digest.
